## Decision

**An unchanged pinned OpenMU runtime cannot meet the proposed strict all-listeners-loopback contract through supported settings.** Game, connect and chat TCP listeners hard-code IPv4 wildcard binding. This is a proved source blocker, not merely an unknown configuration key. Do not start this runtime and then treat a post-start listener check as containment: wildcard sockets already exist before that check.

**A supported graceful source control route does exist:** console input `exit\n`, conditional on persisted `SystemConfiguration.ReadConsoleInput = true`. The shutdown chain awaits normal player disconnect/save attempts. This establishes intended control flow, not successful persistence on the owner's laptop or patched artifact.

A wrapper can be prepared fail-closed, but a working strict-loopback starter remains blocked. A separately approved localized server bind change/rebuild would be needed for this exact contract. Firewall/container isolation would be a different contract and may require security/architecture approval; neither is silently substituted or implemented here.

## 2. Exact graceful shutdown route

Precondition: database-loaded `SystemConfiguration.ReadConsoleInput` is true ([property](https://github.com/MUnique/OpenMU/blob/d067b3c11c23c3145de6e2c76201ab9a93b267c8/src/DataModel/Configuration/SystemConfiguration.cs#L68-L77), [load](https://github.com/MUnique/OpenMU/blob/d067b3c11c23c3145de6e2c76201ab9a93b267c8/src/Startup/Program.cs#L681-L690)). Its actual value in the selected baseline is **UNKNOWN**. This is not an appsettings key proven by source, and no command-line enable override was found in Program. Do not write the database implicitly to make it true.

Supported wrapper design after approval:
1. Own the server process from startup with a writable redirected standard-input stream; keep its identity/handle. Drain redirected output if using it.
2. Once ready, request stop by writing the line `exit` to that process's stdin and flushing. [HandleConsoleInputAsync, L194–204](https://github.com/MUnique/OpenMU/blob/d067b3c11c23c3145de6e2c76201ab9a93b267c8/src/Startup/Program.cs#L194-L204) reads a line and cancels the main exit token.

7. Keep PostgreSQL alive until OpenMU teardown completes. Timeout/failure is a visible stop failure, never permission for automatic force-kill.

### Important limits

- Save errors in RemoveFromGameAsync are caught/logged; boolean save results are not enforced there. Disconnect also has a fallback save attempt with caught errors. A clean process exit or “Server shutted down.” log **does not prove all player data committed**. Runtime acceptance must include an actual targeted saved-state/relog check and no relevant persistence errors.
- Ctrl+C is not the wrapper's proven route: Program's CancelKeyPress handler asks for confirmation but does not set `e.Cancel = true`; do not claim reliable graceful handling from this code. ProcessExit only cancels a token; it does not itself await the entire save chain. Stop-Process/taskkill/window-close are not established graceful controls.
- Pinned docs list `-deamon`, but Program contains no handling of that spelling. Treat source's database flag as authoritative for this route, not the obsolete documentation claim.
- No authenticated HTTP whole-process shutdown route was needed or proved. Console `exit` is sufficient at source level when its preconditions hold; it is not a magic new shutdown flag.
- Patched artifact bytes, retained stdin ownership, actual baseline flag, Windows host behavior, and successful persistence are **NOT_RUN/UNKNOWN** in this source-only task. No readiness increase.
