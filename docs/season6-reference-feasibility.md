# MU Online — feasibility audit: broad Season 6 baseline

**Historical feasibility report. Current findings/owner scope/readiness are superseded by s6-baseline-diff.md and current-state.md (2026-10-10). Prior RED/fix/next-step statements below are preserved history, not current instructions.**
Дата: 2026-10-09. Статус: аудит завершён; импорт и реализация импортёров не выполнялись.

## Решение

Самый быстрый обоснованный путь — сохранить существующую OpenMU-модель и проверенную игровую БД, использовать закреплённые Season 6 initializers/updates OpenMU как основной эталон и выполнить массовую семантическую сверку с точным MuMain/Data. Внешний MuEmu полезен как дополнительный источник различий и отдельных координат/таблиц, но проверенная выборка не является доказанным «known-good standard S6» набором. Полная замена конфигурации не обоснована.

Импорт небольших подтверждённых пробелов технически осуществим и может быть быстрее ручного ввода. Это ещё не доказательство, что внешний импорт быстрее проверки уже заполненной базы: все 68 уникальных map numbers и все 483 monster numbers текущей базы присутствуют в исследованном внешнем наборе. Новые номера там смешаны с поздними сезонами. Не существует измеренного списка недостающего стандартного S6, на который можно честно назначить процент заполнения или календарный срок.

## Качество источников

1. **Основной:** код initializers VersionSeasonSix и унаследованные Version075/Version095d, configuration update plugins из той же закреплённой OpenMU версии. Это наиболее совместимый эталон структуры и серверной семантики; наличие исходника не доказывает полноту gameplay. Installed updates в сохранённой базе: 81; сверка конкретных plugin key/version/initialization key ещё требуется, нельзя запускать их все повторно.
2. **Обязательная клиентская сторона:** точный Data архив и MuMain source/handlers. Клиентские BMD/JSON — эталон доступных ID, размеров, классов/UI/assets, но не серверных drop rates, AI, экономики и event lifecycle. Нельзя заменять ресурсы на другой «S6» пакет.
3. **Внешний кандидат:** [Yomalex/MuEmu, pinned 6b1e8af](https://github.com/Yomalex/MuEmu/tree/6b1e8af3e90155ca6fd1d003b9dae5c978f24186), MIT репозиторий, XML и старые TXT. Репозиторий узнаваемый открытый emulator source, но конкретный Data не подтверждён как чистая официальная S6 configuration. MIT репозитория также не является доказательством прав на все поставляемые игровые assets: assets импортировать не предлагается.
4. **Непригодный для непосредственного переноса запасной кандидат:** MUDevs-Emulator/Default-configuration. Метаданные без declared license; provenance/schema/season не проверены до import-ready состояния. Не тратить время на новый стек или случайные server packs.

Статически прочитаны и распарсены все 8 выбранных XML MuEmu: Maps, Warps_s6, Monster, MonsterSetBase, Items, Skills, Quests, ChaosBox. Дополнительно прочитаны ShopList.xml, Hanzo TXT, ItemBags.xml, BoxOfLuck.xml и исходник ItemNumber encoding. Остальные магазины/bags, QuestWorld/QuestEXP и полные внешние set tables не проверены; им не присваивается coverage. Файлы только прочитаны; их данные не загружены в OpenMU.

- ItemBags содержит повторные bindings одного item/plus, несколько сезонов, разные reward/Zen/option semantics. Один удобный XML parser проблему семантики не решает.

## Почему существующий импорт OpenMU не решает задачу целиком

[MapExportImportService.cs, exact pin](https://github.com/MUnique/OpenMU/blob/d067b3c11c23c3145de6e2c76201ab9a93b267c8/src/Web/Shared/Components/MapEditor/MapExportImportService.cs) — важнее общих обещаний UI documentation:
- BuildExport включает spawns, enter и exit gates.
- ApplyImportAsync очищает существующие MonsterSpawns выбранной карты и загружает только spawns; gates оставляет прежними.
- Monster lookup по Number; неизвестные IDs пропускаются.
- Invalid/version-invalid input может завершиться без информативной ошибки.
Следовательно, даже OpenMU JSON нельзя использовать как безопасный universal merge. Не вызывать этот importer на baseline.

[IConfigurationUpdatePlugIn / DataUpdateService](https://github.com/MUnique/OpenMU/blob/d067b3c11c23c3145de6e2c76201ab9a93b267c8/src/Persistence/Initialization/Updates/DataUpdateService.cs) и JSON persistence инфраструктура дают естественный путь versioned changes. В inspected tree не найден универсальный MuEmu XML/TXT→OpenMU importer. Сначала нужно сверить 81 installed update с pinned plugin versions; это проверка, а не разрешение запускать недостающие plugins без анализа их scope.

## Предлагаемый будущий reusable pipeline — не реализован в этом аудите

**Один нормализованный промежуточный формат**, несколько parser adapters и общий validation/merge planner быстрее семи отдельных ручных переносов. Каждый record хранит source SHA/path/line/key, season admission decision, source units и semantic mapping. Непонятные поля запрещают import record; silent skip недопустим.

Natural keys: map Number + variant/instance purpose; monster/skill Number; item(group,index); gate type+number+map/variant; warp Index; NPC type+placement+store link; shop stock definition+options+grid; set/group identity+membership; quest group+number+giver+class; crafting number+handler; event type+level/variant. Имена только подсказки. Event repeats нельзя dedupe по coordinates.

План результатов: unchanged / add / modify / conflict / unsupported / rejected-later-season. Compare known values/formulas and references; preserve existing UUIDs and player-owned entities. Две стороны client/server проходят одну admission filter. Совместимость только по существованию Number недостаточна.

Dependency order, если позже будет разрешён targeted import: shared attributes/options/classes/skills → items/sets → monster/NPC definitions → maps/terrain and gates/warps → regular spawns/stores → drops → quests/recipes/events with implemented handlers. Cyclic graph references resolve in explicit second pass. Выполнение только на восстановленной копии, transaction+diff before/after, exact configuration identity, deterministic idempotence and rollback validation; никаких writes в player/account/inventory tables.

Эта схема обеспечивает bulk record validation. Она не обещает импортировать AI или state machines и не заменяет proof of gameplay.
