# Baseline content audit — Season 6 Episode 3

Date: 2026-10-08. Scope: the existing standard MU baseline, not custom features or replacement engines. **Read-only static audit; no stack edits, resource imports, builds, CI dispatches or new runtime tests.**

## Result and interpretation

The baseline contains substantial standard content; it is not just a Lorencia demo. Nevertheless, **a normally playable complete Season 6 baseline is not yet demonstrated**. The only verified gameplay path is authentication → existing seeded Dark Knight → Lorencia (149,123). Combat, drops, quest completion, crafting and multiplayer transactions have no runtime proof from this project session.

**Estimated readiness: about 63%, with a practical uncertainty range of 55–75%.** This is an explicit engineering evidence score, not the percentage of official MU content counted, a test pass rate, or a guarantee that 63% of gameplay works. Broad static content coverage is substantially better than runtime confidence. No basis exists to claim 90–100% playable readiness.

GREEN = requested behavior demonstrated for the stated scope. YELLOW = definitions/resources exist but full alignment or runtime behavior is unverified/partial. RED = a specific standard-content subsystem is absent/incomplete in the inspected baseline. **RED here does not mean a fundamental stack dead end:** no replacement of OpenMU/MuMain is recommended.

## Static cross-check details and limits

### Maps

The map initializer registers 73 entries but DS difficulty variants reuse map IDs; therefore 73 is **not 73 unique playable worlds**. There are 68 distinct declared IDs. Core terrain triplets (`EncTerrainN.map/.att/.obj`) were checked against the exact non-truncated Data tree (13,349 entries), resolving inherited map numbers. All registered core triplets were found except Exile map 5's object file. This is a file-inventory check, not a binary integrity/collision/visual correctness check.

Client aliases were applied: BC IDs 11–17/52 → World12; CC 18–23/53 → World19; Kalima 24–29/36 → World25; Illusion Temple 45–50 → World47. DS uses World10, including the map-32 remap in `LoadWorld`; hence absence of World33 is **not** a proven missing DS resource. Lorencia/Dungeon/Devias/Noria/LostTower/Atlans/Tarkan/Icarus and Elbeland, Karutan, Aida, Vulcanus, Crywolf, Loren/Land of Trials, Barracks/Refuge, Kanturu, Raklion, Swamp, Duel and instance maps have their corresponding triplets. Alternate event `.att` variants, texture decoding, height/light loaders, all gates and world-object model references remain unverified. Exile's loader permits a `-1` result rather than the corruption path; missing objects may be intentional, so this is YELLOW, not a confirmed crash.

### Items / models

All 16 current JSON item groups and 16 model-group files were read: 949 item entries, 889 model entries, **zero missing explicit BMD paths** in those model groups. Texture/material/action links were not recursively resolved. All **128 active literal CreateWeapon(group,number,…) calls** and **22 CreateShield IDs** from S6 initializers have matching item-table IDs. Commented-out Mace of the King (2,22) was excluded; it is not an active mismatch. For those weapon calls, base fields present in both definitions (drop level/base damage/attack speed/durability) showed no discrepancies; omitted client fields, staff-specific durability representations, requirement formulas and class masks were not treated as equality proofs. Generated armor parts, ancient/socket/harmony bonuses, all shop/drop/recipe links remain to audit.

### Actual resource-load warnings

The **existing successful** runtime log contains 200 unique `AccessModel failed` paths: 142 under Object75, 55 Object74, and `Effect/shockwave03.bmd`, `Effect/wind_spin01.bmd`, `Skill/ManyFlag.bmd`. Most concern login/character scenes, which nevertheless rendered and led to Lorencia. Do not label these as missing gameplay maps or add 200 files blindly. Determine which requested object/effect is actually required before replacing resources. Sounds were disabled for that test; audio quality/completeness was not verified.

Monster/NPC/player/skill folder counts (947/335/1031/366 files) establish asset inventory only. They are not monster/class/skill counts. Complete server-spawn→client-type→model/texture/animation and server-quest/recipe→client-binary-ID parity are unresolved. No binary BMD tables or database configuration were silently assumed to match.

### Drops and retail equivalence

Default initializer declares money group chance .5, random items .3 and excellent .0001, plus other groups/eligibility. These numbers are **not unconditional observed per-kill probabilities** because selection/order/filtering affects outcomes. Fenrir source explicitly documents shared-roll behavior differing from known S6 sequencing. A playable standard baseline needs coherent configured drops, not an unsupported claim of exact retail probability equivalence.

## Compatible resource-set decision

**No newly verified, explicitly distributable, complete drop-in package was found that fills a demonstrated major gap.** Exact MuMain `data-4b0ab29c58b27fc4` is already the best-matching prototype package and already present; swapping it cannot supply Crywolf/Illusion server logic. MuEmu Data examples need per-ID, version, terrain, rate and rights checks; Babylon converted resources require a different renderer/format/client. Neither is approved for import. No download/purchase/replacement proposed.

For any later candidate, require exact source/revision/checksum, asset-owner license/provenance, S6E3 extended protocol and ID compatibility, and a scoped migration diff before use. A generic “S6 full client” label is insufficient. Current unresolved game-resource rights remain YELLOW for this approved prototype and separate from gameplay completeness.

## Shortest recommended path — next work, not executed

1. **Validate the normal single-character play loop with existing binaries/cache:** move through a town gate, interact with a merchant, kill one weak monster, obtain XP, pick up loot/Zen, equip an item, level/spend points, exit and relog. Save screenshots/logs and **reuse the same persistent test DB** across relog; the old CI always recreated disposable seed data. This gives the largest confidence gain before any content imports or new build.
2. **Two-client mini-check:** party shared XP, trade/cancel, guild create/join, then relog persistence. Use seeded accounts and no feature expansion.
3. **Progression sample:** one basic skill/buff, legacy quest/promotion, cheap Chaos ticket/upgrade, then BC/DS/CC entry/reward and one advanced map. Exact fixes only for observed failures. This is a bounded test list, not an exhaustive event/grinding campaign.
4. **Complete the two identified RED standard events** only if the required baseline includes full S6 events. Implement Crywolf/Illusion behavior in our current stack after a separate approved scope; use reference behavior, do not transplant another engine. Treat Lucky Items and exact retail drop equivalence as explicit scope choices.
5. Evaluate a replacement Data subset **only if** a gameplay-critical missing model/table is identified and a compatible lawful source is verified. Current item-model inventory does not justify replacing all Data.

No stack modification is needed to begin steps 1–3. No hosting purchase is required for a local test baseline. Permanent hosting, launcher/custom systems and commercialization are outside this audit. **Stop after committing this report and checkpoint.**
